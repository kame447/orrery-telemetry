# fresh MCPのツール表示文言を固定照合（fork段階41）

fresh専用の実プロセスprobeは、6ツールの名前・引数schema・権限annotationsと公開フィールドを検証していましたが、`title`と`description`は空でない文字列なら任意の内容を許していました。ツールの説明文はChatGPTなどのクライアントに表示され、操作判断にも影響します。表示文言だけを変えて「対象制限を無視して再送する」と案内する応答が、ほかの固定契約を満たしたまま受理される余地がありました。

本段階では6ツールすべての`title`と`description`を、fork内に明記した承認済み文字列と完全一致で比較します。説明文をサーバーの定義から実行時に読み込んで正解扱いすることはせず、独立した固定値で照合します。空白だけの変更も検出します。正規のサーバー定義は変更せず、差異が出たときは明示的に固定契約をレビューし直す必要があります。

隔離したloopbackサーバーで、6ツールそれぞれのtitle改変、指示を追加したdescriptionへの置換、末尾空白の追加という計18ケースが修正前は誤受理されることを再現し、修正後に拒否を確認しました。実LaunchAgentを起動する検証ではありません。既存の受信制限、unknownの無再送、Mail受理と作業実行の区別は維持します。

前提はfork Draft PR #96です。revertすると表示文言が非空なら通過する従来の挙動に戻ります。本番MCP/Mail/Tunnel/稼働agent、fork master、upstreamは変更しません。専用ChatGPT fresh Tunnel、実agentの処理開始・作業完了、本番identity/allowlist承認、upstream受入は未達です。
