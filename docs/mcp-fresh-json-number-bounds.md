# fresh MCPのJSON数値範囲と深い応答の安全な拒否（fork段階36）

実プロセスの`initialize`、`tools/list`、`orrery_status`に使うJSON-RPC応答を検証する際、`NaN`や`Infinity`という非標準の定数を拒否するだけでは十分ではありません。標準のJSON数値記法`1e999`や`-1e999`は、Pythonのデフォルトのfloat変換で無限大となり、それまでの検査を通過しました。応答の余分なフィールドに含まれる場合でも拒否する必要があります。

`fresh_process_probe`はJSON中の浮動小数点値をすべて有限値として解析し、オーバーフローを拒否します。有限の`1e2`や通常の応答は従来どおり有効です。過度に深いJSONで解析器の再帰制限に達した場合も、未処理例外ではなく`MCP_STATUS_UNVERIFIED`として失敗します。接続所有者、PID、MCP権限の照合は変更しません。応答本文・pairing secretを例外に含めません。

Mac実機のloopback疑似サーバーによる回帰試験は、各RPC段階で正負の指数オーバーフローを扱います。実エージェントの処理開始・完了、専用Tunnelの実ChatGPT接続、本番identity/allowlistとupstream受入は、この修正だけでは確認されません。本番サービスには変更しません。差し戻しは本PRのコード・テスト・日英文書・索引・changelogを一括で取り消しますが、旧動作では範囲外数値を受け入れるため推奨しません。
