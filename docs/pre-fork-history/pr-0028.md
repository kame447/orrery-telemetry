## 原因と変更

従来の `_run_bash` は実行者の environment を全面的に引き継ぎ、bootstrap テストは実際の repository / installed env / registration library を source できました。今回、shell fixture を一時 HOME・install root・runtime・XDG config・テスト専用サービスラベルと、明示された合成環境変数だけで起動します。BASH_ENV / ENV や親の owner token を継承しません。

identity-only テストでは実際の bootstrap 本文を一時 install にコピーし、隣接 env をテスト側が管理します。registration boundary は禁止呼び出しを記録する test double に置き換え、Mail・watcher・managed-agent 書き込みが呼ばれたら失敗します。token の値を stdout / assertion に出す代わりに、clear / preserve / unexpected の分類で従来の stale / reserved identity の意味を検証します。

他の registration テストの合成 token と assertion は維持し、共通 helper から実 HOME へ書き込む経路を除去しました。shell に20秒の上限を設け、一時 HOME は成功・失敗・timeout のいずれでも片付けます。root Claude の fake launcher fixture にも同じ隔離環境を使い、TemporaryDirectory の context manager で例外時にも片付けます。

## 変更前との比較と局所検証

変更前 helper で、外部 BASH_ENV の無害な一時ファイル canary が実行され、外側の HOME を引き継ぐことを再現しました。この再現では bootstrap を起動せず、Mail へ通信していません。

変更後の focused 5件が成功しました。実 bootstrap の stale / reserved 比較、親 HOME / token / startup hook の非継承、失敗時 cleanup、timeout 時 cleanup、汚染した親環境からの bootstrap fixture 実行を含みます。構文検査も成功しています。ローカルで実行したのはこの5件であり、他の8件の既存テストまでローカル実行したとは扱いません。

テストの検出力も確認しました。一時コピーした bootstrap に対して、stale parent/token のクリアを壊す、reserved name の保持を壊す、project を設定して禁止した Mail boundary を呼ばせる、という3つの限定的な改変を加え、すべてテストが失敗することを確認しました。実ファイル・サービス・credential を改変したものではありません。

ローカルは Linux の対象ファイル検証です。bootstrap 入力 blob `d17e8c4987b39610c96656e3cda8e59446be1c22` と元テスト blob `7d98353e2bd6dd5d7566a04299be9bdb95ac0035` は upstream base と照合済みです。GitHub に保存した最終テスト blob `8c190784dad16cdac9adbdb36f9715ec9e80b7f4` と、局所検証したファイルの一致も確認しています。
