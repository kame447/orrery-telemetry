## Original description

~~~~markdown
## 概要

CI が feature branch の push と pull_request の両方で二重起動し、さらに古い queued run が残って macOS runner 待ちを悪化させていたため、workflow trigger と concurrency を整理します。

## 変更

- `push` は `master` のみに限定
- feature branch は `pull_request` 経路だけで検証
- 同一 PR / ref の古い run は `cancel-in-progress: true` で自動キャンセル

これにより、PR中の1回のpushで同じCIが二重に起動する状態を避け、連続push時も最新runだけを残します。

Gemini provider の実装変更とは分離したCI基盤修正です。
~~~~
