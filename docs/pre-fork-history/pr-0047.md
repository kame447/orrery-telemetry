## Original description

~~~~markdown
Project A の通知が、同名の project B の tmux pane や共有 delivery state に流れる問題を防ぎます。Issue gyroid-eth/orrery-telemetry#33 の Phase 5 として、Phase 4 (`fix/issue33-direct-child-ownership`) に積んだ通知の責務です。

- producer は signal に canonical `project.human_key` を含め、delivery state と短期 lease を `(project, agent, message)` で分離します。
- watcher は具体的な pane/session ID、実 cwd、全ての存在する context marker、private credential、bundled Mail の owner proof を確認してから capture します。session 環境の取得失敗や認証中の変化は pending のままです。
- 文字列送信と Enter の直前にも同じ境界を再確認します。tmux の二つの操作を atomic にするものではありません。
- slug だけの旧 signal は、対応する Mail resource が canonical project を一意に返す場合だけ扱います。resource が未提供・不明な場合は pending とし、推測しません。

既存の importance、cooldown、TTL、crash-window、unlink の条件を維持しています。新たな owner DB や共通 orchestration layer は追加していません。Dashboard の reads/controls は Phase 6/7、doctor/install の残りは Phase 8 です。

- 専用 regression: 51 passed。実 tmux 3.7c の隔離 socket で exact-session 配信、prefix-only 拒否、foreign-project 拒否を検証しました。pane lookup は実 tmux の target-pane 文法 `=name:` を使用します。
- 最終関連 tests: 43 passed / 3 intentional frozen-predecessor skips。実 bundled HTTP Mail の owner/stranger、session marker・pane・token 変更、環境取得失敗、両送信直前の再検証を維持しています。
- 一試行を確認する mutation test は既存の bounded quiet-event fixture を使い、pending・正確な送信回数・Enterなしの assertion を維持しています。
~~~~
