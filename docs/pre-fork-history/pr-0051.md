## 修正内容

- `jump / resume / kill / exit / reactivate` が別projectの同名tmux sessionを操作しないよう、既存のDashboard project attribution primitiveでfail-closedにします。
- resume時にtarget workspaceからproject contextを再検証し、tmuxへ project key / repository identity / work dir / worktree root / protected roots / context JSON を一組で注入します。
- Dashboard spawnはMail registrationを直接先行させず、既存の `agentstack-preregister-child` とstrong ownership contractを再利用します。
- delegated childはDashboard projectとworkspaceが一致すること、parent registration/token ownershipが同projectであることをside effect前に検証します。
- standalone childは指定workspaceから解決したproject contextを使い、ambient project keyを権威にしません。
- child handoffの一時tokenだけをDashboardがcleanupし、preregistrationが確立したdurable owner credentialは削除しません。
- control isolation regressionを追加し、既存spawn / Gemini / reactivate / exit testsを新contractへ追従させます。
