## 位置づけと原因

Refs gyroid-eth/orrery-telemetry#33
Refs kame447/orrery-telemetry#16

旧 kame447/orrery-telemetry-pre-fork-history#32 の Dashboard 変更から、`dashboard/graph_data.py` の読み取り境界だけを分離しました。既存 `_resolve_project_id` は configured human key が見つからない場合も project ID 1 にフォールバックするため、存在しない project を選択したときに別 project の graph を返す可能性があります。

この PR は graph builder の境界を修正し、後続の Dashboard server が明示 project と検証済み live lineage を渡せる API を用意します。server.py、NEW AGENT、exit / kill、launcher、Mail storage、reservation は変更しません。

Base: `65cd9e0605fffea089339d61bbca00fd13dfc723`
HEAD: `03ecb9670e8ac2984d6c884477bb4e5fbbb3f968`

## 変更

configured-but-unknown project key、明示された空の project key、project lookup の SQL エラーを project 1 の表示へ変換しません。project を全く設定せず引数なしで実行する従来 standalone モードの default は維持します。設定済みの project が未登録の場合は、別 project の情報ではなく空の graph になります。

`build_graph(project_human_key, live_parents)` で明示 project を受け取れるようにします。明示 project 呼び出しでは host-global tmux lineage cache を参照せず、呼び出し元が対象 project に所属すると検証した child→parent mapping を受け取ります。mapping を省略した場合は live lineage を追加しません。DB 由来の既存 message / spawn / timestamp 集計は維持します。

グラフ builder 自体が runtime ownership を新しく推測する実装ではありません。渡す mapping の project 所属判定と、新 API を Dashboard server から使用する変更は後続 PR の責務です。この PR だけで Dashboard 全経路の isolation が完成したとは扱いません。

## 参照実装との関係

製品コードは包括候補 `5c061e6` の graph builder の差分を抽出しています。包括候補にある「Dashboard が常に明示 project を渡す」というコメントは、中間段階ではまだ成立しないため、呼び出し元への契約として書き直しました。no-argument fallback のコメントも実際の挙動に合わせました。新しい動作仕様を追加したものではありません。

既存 server 側の関数呼び出しや timestamp 互換テストは変更しません。既存 timestamp test の fixture 調整を一緒に移すと server.py の未移行 API まで依存するため、独立したテストファイルを追加しました。

## 検証

Linux の局所 pytest で14 passed / 5 subtests passed、直接 unittest で14件成功しています。ResourceWarning を error として扱う実行でも成功しました。SQLite connection は fixture の transaction 後に明示的に閉じます。

一時 SQLite に2つの project と同名 agent を用意し、未登録 project、明示空値、プロセス既定値の上書き、project の連続切り替え、message / activity の分離、scoped lineage、空 mapping、legacy standalone、SQL parameter binding、DB 不在・lookup エラーを検証しました。各テスト後に DB bytes が不変であることも確認します。

module import の前に test DB path を明示し、全 host command を失敗する test double にしています。実 Mail DB、live listener、tmux、実 credential に触れていません。

変更前の正確な graph blob `e3bffcc4b38b0ff62d3792139f35609b0df6c45e` でも検証しました。未登録 configured key のテストは project 1 の nodes を実際に返して失敗し、新 API を要求するテストも失敗します。旧実装での pytest 表示は subtest を含め15 failed / 2 passedでした。
