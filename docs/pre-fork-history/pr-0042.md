## 修正する問題

Edit / Write の予約確認が、継承した別projectのprotected rootsやhook process自身の古いcwdで対象pathを分類すると、確認を迂回したり、別namespaceの予約を解除したりする可能性がありました。予約hookはpayloadの実際の `cwd` を必須とし、選択projectとworkspaceを検証した後に、canonical project keyで確認・解除・SessionEndを処理します。

linked worktreeは同じrepository namespaceを共有しつつ、実際のworktreeを保護します。symlinkと `..` を正規化し、他repositoryの設定済みrootで実際のworkspaceを置き換えません。contextが不明または不一致なら、編集前のguardはMailへ接続せずblockし、解除hookは問題を記録して送信をskipします。

遅延解除のslotはproject・agent・pathで分離します。共通のrelease境界では旧形式のprojectを含まないworker、部分的なworker context、置換済みtoken、別projectのslot、symlinkのslotを拒否します。通常の即時解除と有効なproject-scoped workerは維持します。旧checkoutを直接参照して実行中のworkerは、更新済みlibraryを読まないためcutover前にdrainする必要があります。この制約も日英のhook文書に記載しています。
