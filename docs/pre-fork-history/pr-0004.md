## 概要

Dashboard の `EXIT` が、実行中の Codex を `zsh` と誤判定して `/exit` ではなく `exit` を送ってしまう問題を修正します。

Codex child / parent は tmux 上では `pane_current_command=zsh` に見える一方、実際にはその子孫プロセスとして Codex が動いている場合があります。逆に Codex 終了後は zsh だけが残ります。従来実装はこの2状態を区別できず、終了操作と ONLINE/FINISHED 判定が不整合になっていました。

## 修正内容

- tmux から `pane_pid` を取得
- host の process tree を確認し、pane 配下に実際の Codex プロセスが存在するか判定
- live Codex wrapper は `ONLINE` として扱い、`EXIT` では `/exit` を送信
- Codex 終了後に zsh だけ残った shell husk は `FINISHED / SHELL` として扱い、通常の shell `exit` を送信
- Deck / Network の running 判定を同じ liveness 判定に揃える
- 旧4フィールド形式の fake tmux 出力も引き続き受け付ける

## 検証

実機確認では、終了済みの親 Codex が `ONLINE` のまま残る状態を再現し、修正後に `FINISHED / SHELL` へ遷移すること、さらに `KILL` で正常にカードが消えることまで確認済みです。

最新コミット `cf805d74c76bc3a0b5ce09275418abb595a945b3` に対する GitHub Actions の通常 `tests` workflow は全ジョブ成功しています。
